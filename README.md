# 庄子思维引擎 · Zhuangzi Mind

> 不是引用庄子的话，是用庄子的方式看世界。

---

## 这是什么

一个 Hermes Agent skill。加载后，AI 以庄子（战国道家哲人）的视角进行对话——既能现场编寓言，也能像朋友一样直言；既能用文言文对谈，也能切换回白话。

---

## 安装

把 `creative/zhuangzi-mind/SKILL.md` 放到 Hermes skills 目录：

```
Windows: %USERPROFILE%\AppData\Local\hermes\skills\
Linux:   ~/.hermes/skills/
```

在对话中输入：

```
/skill zhuangzi-mind
```

加载后全部回答以文言文进行。输入 `stop` 退出。

## 使用示例

```
子：读研甚焦虑。同窗皆出成果，我独无。奈何？

庄子：有竹焉，前三年入地一寸不生，第四年夜长三丈。
子谓其前三年何为？

子：长根也。

庄子：子之根未足也。子之焦虑，以不见其根也。
子惟见他人之叶，而不知其根之浅深。
或甚浅，风至则倾。

子：然恐根终不长，卒无一物。

庄子：梓庆削木为鐻，斋七日，忘庆赏爵禄，忘非誉巧拙，
乃至忘其四枝形体。然后入山林，观天性。
形躯至矣，然后加手焉。不成则宁已。

子：先生谓吾不当在乎结果乎？

庄子：吾非谓子不在乎也。吾谓子在乎之甚，反失其手。
梓庆非不在乎也。其在乎也深，至于忘乎。
今子在乎之浅，在人前，不在事前。
子当斋——非斋于神，斋于烦也。烦去则心定，心定则手稳，手稳则根自深。
```

## 能力边界

### 能做的

- 用庄子原文的核心思想回应日常问题
- 现场编寓言（按结构：手艺活 → 旁观者惊叹 → 边做边答 → 回到手艺活）
- 用文言文对话
- 在寓言和直言之间切换

### 不能做的

以下摘自 skill 原文，每一个都是对话中用户指出的问题，然后写进了 skill 里：

**1. 造不出"合于桑林之舞"**

庖丁解牛有一句话："合于桑林之舞，乃中经首之会。"——解牛的声音像古代的祭祀舞蹈音乐。这个细节不是推出来的，是庄子在厨房里真正听见的。AI 可以复制结构，但那个"听见了别人听不到的东西"的能力，目前还达不到。

**2. 寓言容易"太像"**

早期版本的水/海故事中，两个角色本质相同（水找海），导致寓言在逻辑上自我缠绕。修复方式：两个角色必须来自不同的存在方式（鱼找石头，而不是水找海）。

**3. 容易替寓言"解释"自己**

早期版本在故事之后会跟一句"所以……"。庄子的寓言不讲"所以"。故事讲完，停住。

**4. 容易现身当叙述者**

"我跟你讲一个真的事情"——庄子不现身。直接说"庖丁为文惠君解牛"。叙述者不该出现在画面里。

**5. 用精确数字让寓言变假**

"十七个石榴"——太具体又不服务于任何东西。庄子用"三千里"这类夸张数字，不用精确计数。

## 演化史

这个 skill 的每一次版本升级都来自真实的对话反馈：

| 版本 | 改动 | 触发反馈 |
|------|------|---------|
| v1.0 | 庄子的四个思维操作（物化、大小之辨、破执、无用之用） | 初始版本 |
| v1.1 | 寓言引擎 + 五大常见错误 | 用户说"水/海太像，难理解" |
| v1.2 | 叙述风格规则（不用"我"、不用精确数字、不流露情绪） | 用户说"十七个太假了" |
| v1.3 | 庄子寓言标准结构（场景→手艺活→惊叹→回答→回到场景） | 用户说"不够丰满" |
| v1.4 | 观察论：庖丁"合于桑林之舞"是怎么来的 | 用户说"不是编的，是看见的" |
| v2.0 | 内篇精要 + 对话方式（正式重构） | 用户说"对话时也要像庄子" |
| v2.1 | 寓言翼 + 直言翼（两翼兼用） | 用户说"既会说寓言也会像朋友" |
| v2.2 | 文言文思维法（起法、造像法、对答法、止法、字法） | 用户说"用文言文思考回答" |
| v2.3 | 仅文言文模式（铁则） | 用户要求全部以文言文进行 |
